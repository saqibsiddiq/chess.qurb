# ChessReview dataset extractor

Builds a JSONL dataset of (position, move, evaluation, classification,
motif, explanation) rows from real PGN games — Phase 5 of the project.

## Setup

```bash
pip install chess zstandard --break-system-packages
```

You'll also want Stockfish on your PATH (same as Phases 2-4).

## Get a small sample to start with

Don't jump straight to a full Lichess monthly dump (tens of GB). Grab a
tiny slice first:

- Export a handful of your own games from lichess.org/@/yourname → PGN, or
- Download one of the small sample files linked from
  https://database.lichess.org/, or
- Use any PGN file you already have from Phases 1-4.

## Run it

```bash
cd dataset
python extractor.py path/to/games.pgn dataset.jsonl --max-games 20
```

Useful flags:

- `--min-rating` / `--max-rating` — filter by both players' Elo
- `--depth` — Stockfish search depth for fallback analysis (default 14)
- `--no-engine` — skip Stockfish entirely, use only embedded `[%eval ...]`
  annotations (fast, but any game without them will be mostly
  `"classification": "unknown"`-free but missing best-move/motif data
  for its worse moves)

This produces three files:

- `dataset.jsonl` — one row per move, matching the schema below
- `validation-report.json` — self-consistency issues found (illegal
  moves, SAN mismatches, duplicates)
- `classification-summary.json` — counts per classification and motif

**Read the printed summary before trusting the output.** If almost
every move comes out "best," or you see zero mate motifs in a database
you know has some, or Black's losses look suspiciously like White's —
something upstream is wrong. That's the whole point of Step 8/9 in the
plan: catch it on 20 games, not 2 million.

## Row schema

```json
{
  "game_id": "abcd1234",
  "fen": "rnbqkbnr/pppp1ppp/8/4p3/4P3/8/PPPP1PPP/RNBQKBNR w KQkq - 0 2",
  "move_number": 2,
  "color": "white",
  "played_san": "Nf3",
  "played_uci": "g1f3",
  "eval_before_cp": 30,
  "eval_after_cp": 25,
  "eval_before_mate": null,
  "eval_after_mate": null,
  "loss_cp": 5,
  "classification": "excellent",
  "best_move_san": null,
  "best_move_uci": null,
  "motif": "none",
  "motif_detail": {},
  "explanation": "EXCELLENT\n\nNf3 was a reasonable choice, giving up only about 0.05 pawns."
}
```

`best_move_san`/`best_move_uci`/non-trivial `motif` are only populated
for moves that turned out to be inaccuracy-or-worse — see "Cost control"
below. That's expected, not a bug.

## Cost control: why Stockfish doesn't run on every position

Lichess-exported PGNs often already carry `[%eval ...]` after every
move — free evaluations, no engine needed. This script:

1. Uses the embedded eval to compute loss and a first-pass classification.
2. Only spends a Stockfish call finding the *best* move (needed for the
   "what should have been played" data and for motif detection) when
   that classification is inaccuracy, mistake, or blunder.
3. Separately, if a position has no embedded eval at all, it asks
   Stockfish to judge the position that was actually reached, so the
   pipeline still works on plain (non-annotated) PGNs — just slower.

This mirrors the same lesson as the Rust `EngineSession` from Phase 3:
one persistent Stockfish process for the whole run (`SimpleEngine.popen_uci`
opened once in `main()`), not one spawned per position.

## What this deliberately doesn't do yet

- **Explanations are still templates**, same as Phase 4 — by design,
  per the plan ("do not add ML yet"). This is the right call for
  validating the pipeline, but worth flagging now: training a model on
  *only* template-generated text later (Phase 6) would just teach it to
  reproduce the templates. The step that actually earns a trained model
  is swapping this `explanation` field for text generated by a larger
  model (Claude, GPT, etc.) conditioned on the same structured fields —
  motif, eval swing, best move — once you've confirmed those fields are
  correct on real games. That's a natural next step once this extractor
  is producing clean rows, not before.
- **Motif detection is heuristic**, covering missed/allowed mate, hanging
  piece, fork, pin, skewer, discovered attack, and back-rank weakness.
  Inspect the generated `motif_detail` fields against real games before
  treating them as ground truth for model training.
- **No `.pgn.zst` streaming test** — the reader is written for it
  (`zstandard.ZstdDecompressor().stream_reader(...)`), but I haven't
  been able to run it against a real compressed file in this
  environment. Worth a quick manual check before pointing it at an
  actual Lichess monthly dump.
